# AI Stack с Ollama и веб-интерфейсом

Полнофункциональный стек искусственного интеллекта с локальными LLM моделями
и современным веб-интерфейсом.

## 🚀 Возможности

- **Локальные LLM модели** через Ollama
- **Веб-интерфейс** Open WebUI (аналог ChatGPT UI)
- **Голосовой ввод/вывод (STT/TTS)** средствами WebUI (доступно при HTTPS-подключении)
- **Встроенная панель управления ресурсами** с графиками и управлением
  моделями в реальном времени
- **Автоматическая загрузка моделей** из конфигурационного файла
- **HTTP/HTTPS поддержка** через Nginx (самоподписанные сертификаты для HTTPS)

## ⚡ Быстрый старт

### Предварительные требования

- **Docker** и **Docker Compose**
- **Минимум 8 ГБ ОЗУ** (рекомендуется 16+ ГБ)
- **20 ГБ свободного места** на диске для моделей
- **Доступ в интернет** для загрузки моделей
- **NVIDIA GPU** (рекомендуется для лучшей производительности)

### Установка и запуск

1. **Клонируйте репозиторий**

   ```bash
   git clone https://github.com/NikitaShubin/SelfHostedAI.git
   cd SelfHostedAI
   ```

2. **Настройте модели** (опционально)
   Отредактируйте файл `models.txt`, раскомментировав или дописав нужные модели:

   ```bash
   nano models.txt
   ```

3. **Запустите стек**:

   ```bash
   ./run.sh
   ```

   Если какой-либо порт уже занят другим сервисом, скрипт автоматически
   подберёт первый свободный (например, занятый `8080` → `8081`) и продолжит
   запуск, не прерывая весь стек. Для строгого режима (остановки при занятом
   порте) используйте `./run.sh --strict` или переменную `STRICT_PORTS=1`.

4. **Дождитесь загрузки моделей** (может занять время в зависимости от выбранных
   моделей и скорости интернета)

5. **Откройте в браузере**:
   - Веб-интерфейс (HTTP): <http://localhost>
   - Веб-интерфейс (HTTPS): <https://localhost>
   - Прямой доступ к WebUI: <http://localhost:8080>
   - Ollama API: <http://localhost:11434>
   - Панель управления: <http://localhost:5000>

> **Примечание:** Некоторые браузеры могут автоматически переключать HTTP на HTTPS.

## 🎯 Использование

### Веб-интерфейс (Open WebUI)

1. Откройте в браузере:
   - **<http://localhost>** (HTTP, без предупреждений)
   - **<https://localhost>** для поддержки голосового общения
     (HTTPS, с предупреждением о самоподписанном сертификате)

1. При использовании HTTPS примите самоподписанный сертификат
1. Зарегистрируйте нового пользователя или войдите
1. Выберите модель из списка загруженных
1. Начните общение с ИИ (через HTTPS доступно использование голосвого ввода/вывода)

### API Ollama

Прямое обращение к Ollama API доступно по адресу:

```bash
# Список моделей
curl http://localhost:11434/api/tags

# Генерация текста
curl http://localhost:11434/api/generate -d '{
  "model": "qwen2.5-coder:7b-instruct",
  "prompt": "Привет, как дела?",
  "stream": false
}'

```

## 📊 Панель управления

### Веб-интерфейс панели управления

Стек включает встроенную панель управления: мониторинг ресурсов и выгрузку моделей Ollama:

- **URL**: <http://localhost:5000>

Настраивается в `docker-compose.yaml`:

```yaml
environment:
  - UPDATE_INTERVAL=${DASHBOARD_UPDATE_INTERVAL:-1}  # Интервал обновления в секундах
  - RETENTION_TIME=${DASHBOARD_RETENTION:-60}        # Время хранения истории в секундах
```

### Переменные окружения

В `docker-compose.yaml` можно настроить:

- `OLLAMA_KEEP_ALIVE`: Время хранения моделей в памяти
- `OLLAMA_HOST`: Адрес сервера Ollama
- `HF_HUB_OFFLINE`: Режим работы с HuggingFace
- `UPDATE_INTERVAL`: Интервал обновления метрик в секундах
- `RETENTION_TIME`: Время хранения истории метрик в секундах

### Порты

Хост-порты конфигурируются переменными окружения (с дефолтами из
`docker-compose.yaml`). Если порт занят, `./run.sh` в обычном режиме подберёт
свободный:

- `OLLAMA_PORT` (дефолт `11434`): Ollama API
- `WEBUI_PORT` (дефолт `8080`): Прямой доступ к Open WebUI
- `NGINX_HTTP_PORT` (дефолт `80`): HTTP (веб-интерфейс без шифрования)
- `NGINX_HTTPS_PORT` (дефолт `443`): HTTPS (веб-интерфейс с шифрованием)
- `DASHBOARD_PORT` (дефолт `5000`): Панель управления ресурсами

Мониторинг (`./monitor.sh`) автоматически читает фактические порты из запущенных
контейнеров, поэтому всегда показывает актуальные адреса.

### Настройка моделей

Для внесения новых моделей в систему добавьте их названия в список `models.txt` и
выполните перезапуск:

```bash
./restart.sh
```

Удаление или комментирование строк в списке не приведёт к удалению уже установленных
модели из системы.

Размеры моделей:

- **7B модели**: ~4-5 ГБ, работают на CPU (медленно) или GPU
- **8B модели**: ~5-6 ГБ, хороший баланс качества/скорости
- **20B+ модели**: 10+ ГБ, требуют много памяти и GPU

### SSL-сертификаты и подключение с других устройств

Стек автоматически генерирует локальный **корневой CA** и серверный сертификат,
который покрывает **все внешние IP** машины (все сетевые карты определяются
автоматически, ничего прописывать вручную не нужно). Файлы хранятся в
`./data/nginx/`:

- `ca.crt` / `ca.key` — корневой CA (создаётся один раз)
- `localhost.crt` / `localhost.key` — сертификат для `https://<внешний_ip>`
- `san_hash` — хеш набора IP; сертификат перевыпускается только при смене IP

**Проще всего через дашборд:** на странице панели управления есть кнопка
«🔐 Сертификат» (и страница `/cert`), которая служит ссылкой на эндпоинт
`/cert` — там и сам файл `ca.crt` для скачивания, и пошаговая инструкция по
установке для разных ОС, и пояснение, зачем это нужно (без CA не работают
голосовой ввод STT и озвучка TTS). Файл также лежит в `./data/nginx/ca.crt`.

**Импорт CA на клиенте (обязателен один раз на каждом устройстве):**

Браузеры блокируют доступ к микрофону/камере на недоверенном origin, поэтому
без установки `ca.crt` голосовой режим не заработает. Скачайте свежий `ca.crt`
(через дашборд → страница `/cert` → кнопка «Скачать сертификат», или из
`./data/nginx/ca.crt`) и добавьте в доверенные:

> **Важно для Яндекс Браузера и Chrome на любой ОС:** они используют собственное
> хранилище доверенных сертификатов. Поэтому основной способ — импорт CA именно
> в браузер через `browser://certificate-manager/` (в Chrome — `chrome://certificate-manager`),
> раздел «Персонализированные» → «Доверенные сертификаты» → «Импорт», затем **полный
> перезапуск браузера**. Системной установки (`update-ca-certificates` на Linux,
> `certmgr.msc` на Windows) часто недостаточно — сайт останется «Не защищено»,
> а микрофон будет заблокирован.

- **Яндекс / Chrome (все ОС) — основной способ:** открыть `browser://certificate-manager/`
  (в Chrome — `chrome://certificate-manager`) → «Персонализированные» → «Доверенные
  сертификаты» → «Импорт» → выбрать `ca.crt` → подтвердить импорт → полностью
  перезапустить браузер.
- **Linux (системно, для curl/openssl):**  
  `sudo cp ca.crt /usr/local/share/ca-certificates/selfhosted-ai-ca.crt`  
  `sudo update-ca-certificates`
- **Windows (системно):** `certmgr.msc` → Доверенные корневые центры сертификации → Импорт → выбрать `ca.crt`
- **Android:** Настройки → Безопасность → Ещё настройки безопасности → Установка сертификатов → Сертификат CA → `ca.crt`

После установки CA **разрешите микрофон** (значок у адресной строки → «Микрофон» →
«Разрешить», или `chrome://settings/content/microphone`) и обновите страницу.
Взаимодействие должно идти по `https://localhost` или `https://<любой_внешний_ip>` —
без предупреждений и с работающим голосовым режимом (STT/TTS).

> **Примечание по TTS (озвучке) на Linux:** Chrome/Яндекс на Linux не поддерживают
> Web Speech API (из-за ограничения Chromium). Если озвучка ответов (значок 🔊)
> не работает — используйте **Firefox**. На Windows/macOS озвучка работает
> в любом браузере.

**При перезапуске (`./restart.sh`) обновлять доверие на клиентах не нужно** —
CA стабилен, сертификат перевыпускается автоматически только при смене набора IP.

### Вывод в продакшен

1. Замените сертификаты в `./data/nginx/` на полученные от Let's Encrypt
2. Обновите `nginx.conf` для использования реальных доменов
3. Настройте брандмауэр для доступа только к необходимым портам

### Рекомендации по безопасности

1. Не используйте в публичных сетях без настройки аутентификации
2. Ограничьте доступ к портам 11434 (Ollama API) и 8080 (WebUI)
3. Регулярно обновляйте образы Docker
